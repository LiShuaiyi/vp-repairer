# MICP–VP pilot 实验结果（2026-09-03）

> 历史结果：本报告生成于双积分器、monitor 等价规则和 fewer-binary 修复之前；
> 当前实现的验证请参见 `results/regression_v5_smoke_2026-09-04/`。

## 结论

在每个规则组按 VP batch 顺序选取前三个唯一 case（共 24 个）的 pilot 中，二维
MICP 有 15/24 个 case 返回可行解，12/24 个通过原始 `STLRuleMonitor`，验证准确率
为 50.0%（Wilson 95% CI 31.4%–68.6%）。相同 case 上 VP 成功 23/24（95.8%）。

MICP 全部尝试的 core-time 中位数为 0.507 s；VP 在同一批 case 的 core-time 中位数
为 0.0099 s，两个中位数相除约为 51 倍。只在双方都成功的 12 个 paired case 上，
MICP/VP 时间比的几何均值为 76.7 倍。两种数字回答不同问题，不能混用。

## 实验口径

- VP 没有重新运行；VP 成功状态和 core-time 直接读取仓库已有的
  `evaluation/config/vp_temporal_full/vp_repairer_*_batch_result_updated.csv`，本次只新跑
  MICP，并按 `(scenario_id, ego_id, rule)` 与已有 VP 行配对。
- MICP 状态为 `[s,d,v_s,v_d,a_s,a_d,j_s,j_d]`，输入为两个方向的 snap；没有
  `d=0` 约束。reference path 只定义 CLCS，因此这是 longitudinal+lateral replan。
- `core_total_time = specification_time + solver_setup_time + solve_time`；最终 monitor
  validation 单列，不计入 core time。
- `solver_feasible` 只表示近似 MICP 有解；只有 `monitor_compliant=True` 才计成功。
- Gurobi 每 case 上限 30 s；本 pilot 每 case 运行一次，没有 warm-up/repeat，因此只能
  作为方向性结果，正式论文统计应扩大样本并重复至少 5 次。
- R_G1/R_G2/R_G3 使用仓库历史 MICP 的线性化思想；R_IN1 使用“不越过停止线”的
  保守策略；R_IN3/R_IN4/R_IN5 使用目标冲突占用窗口内避开二维冲突区的保守策略。
  这些近似产生的 false positive 已由最终 monitor 拒绝并计入失败。
- R_IN3 的一个 case 在几何触发步转换时出现 infinity-to-int 错误，也按失败统计。

原始 CSV 与机器可读汇总位于 `results/pilot_n3_*.csv` 和
`results/pilot_n3_summary.json`。
